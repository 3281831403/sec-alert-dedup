# sec-alert-dedup

同一个漏洞被扫出两百条告警，运维全忽略了，真正的那条提权告警也一起被埋了：告警必须先按实体、规则与严重度算出的指纹分组，同一指纹在同一个时间窗口内只保留一条主告警，后来重复出现的告警并入这条主告警并把重复次数累加，重复次数达到策略阈值或严重度达到策略设定的升级级别时要给出升级标记，升级之后必须重新触发通知，不同严重度的同类告警不得合并，窗口向前滑动后旧指纹要被释放，新窗口里的同指纹告警重新开始一条主告警，批量去重时每一批都独立开始，不继承上一批的计数。不变量有两条：同一批告警连续去重两次结果完全一致；去重过程不得丢失任何告警的指纹。

## 契约

告警字段：alert_id 告警编号，entity 实体名称，rule 规则名称，severity 严重度，timestamp 发生时间，repeat 这条告警代表的重复次数，缺省为 1。

策略字段：window_seconds 窗口长度，单位是秒；escalate_after 触发升级的重复次数阈值；escalate_severity 需要立即升级的严重度，可选。

状态字段：entries 以指纹为键的主告警表；sequence 已经创建过的主告警条数。主告警包含 fingerprint、entity、rule、severity、alert_id、window、window_seconds、first_seen、last_seen、count、notified、escalated、notes。window 是主告警所在窗口的编号，从 1970-01-01 起按窗口长度整除得到。notified 为 False 表示这条主告警还有通知没有发出，调用方发出通知后把它置为 True。

## 接口

fingerprint 接收一条告警，返回由实体、规则与严重度构成的指纹字符串。

window_of 接收一条告警、当前时间与窗口长度，返回该告警时间戳所属窗口的编号。

absorb 接收状态、告警、当前时间与策略，把告警并入对应的主告警并返回这条主告警。同一指纹在同一个窗口内只保留一条主告警，重复次数累加；告警落入新的窗口时开始一条新的主告警。

escalate 接收状态、告警与策略，返回这条主告警当前是否已经达到升级条件。

release_expired 接收状态、当前时间与策略，释放窗口已经滑过的指纹，返回释放的条数。

severity_rank 接收严重度名称，返回由低到高的次序值。

validate_state 接收状态，返回问题说明组成的列表，覆盖计数为负、窗口倒序与缺少指纹三类问题。

dedup_batch 接收若干批告警、当前时间与策略，返回每一批的摘要。摘要里 fingerprints 是该批出现过的指纹列表，counts 是指纹到重复次数的映射，mains 是指纹到主告警编号的映射。各批次互不影响。
